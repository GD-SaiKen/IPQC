## 1. 目标

一句话：数据一次录入、全厂口径一致、异常自动预警、处置有据可查。

工作台服务品质保证部前制程：把首件 / 巡检、终检 FQC、零件投诉、过程点检、培训技能、工作绩效六类台账收成同一套月度目视化，让主管「一眼看清全厂、一键下钻车间」，让 NG 与投诉按流程留痕。

| 目标 | 做到什么程度 | 可观察标准 |
|---|---|---|
| 口径统一 | 6 个责任区共用同一套指标定义、满分与目标 | 总看板与子工作台同车间、同月数字可对上；无数据写「—」，有数据才出现百分数 |
| 异常可视 | 首件 NG、终检高不良、投诉未结案、点检未达标、重复投诉自动出现在关注区 | 不靠人工翻表才能看见预警 |
| 处置闭环 | 首件 NG 按 5 步留痕：即时隔离、5 分钟反馈、15 分钟介入、无对策不得生产、复检结案 | 每条 NG 能看到反馈分钟、介入分钟、状态与确认角色 |
| 决策支撑 | 月度例会直接用总看板汇报 | 可切「全年 / 单月」，可打印或另存 PDF |

## 2. 范围

### 本期做什么

建设品质保证部 **IPQC 智能质量工作台**：总看板 → 车间子工作台 → 业务模块。数据周期 **2026 年 1–10 月**，月份切换为「全年」与 1–10 月。

责任区固定 6 个：`注塑`、`注塑毛边`、`压铸`、`五金`、`涂装`、`印刷`。方案引言里的「冲压」是前制程工艺描述，不是第 7 个责任区。

优先级与本期关系：

| 优先级 | 模块 | 本期 |
|---|---|---|
| P0 | 总看板（对比表、投诉走势、点检走势、热力矩阵）、车间总览、首件巡检（含标准索引）、终检 FQC、投诉闭环、点检 | 必须交付，见第 7 节 |
| P1 | 绩效、培训、数据口径说明 | 必须交付。原型已包含，且口径说明是「数字可追溯」的目标 |
| P2 | 移动端 / 平板 | 不做验收 |
| P2 | 数据导出 | 按第 1.2 节纳入本期（JSON、CSV、打印 / PDF） |

### 明确不做什么

- 不建设账号、RBAC、AD / SSO。各角色看同一套界面，用车间维度区分。
- 不实现服务端持久化、多人实时协同、消息推送。
- 不对接 MES / ERP / 文控在线接口。标准文档是索引：可搜索、可按类型筛选；浏览器能预览的类型可打开，CAD 只做链接，不做在线编辑器。
- 不改既有 Excel 源表的目录结构与文件名。重建种子数据另期，若需要再写抽取 SDD。
- 不把点检按毛边适用项折算成百分制后再排名。
- 不在页面调用模型自动填数。保存与重算由本地逻辑完成。
- 不修改 `.github/` 自动开发流水线（见 [26-11-06 组织级自动开发流水线](./26-11-06%20组织级自动开发流水线.md)）。
- 不把「全部车间」当成可编辑的业务车间。`全部` 只存在于总看板筛选。

## 5. 业务规则（必须一致）

### 5.1 空值

无台账、无得分、分母为 0 时显示 **「—」**。禁止用 `0` 或 `0%` 表示「没有这块数据」。注塑毛边首件合格率即此规则。

### 5.2 总看板六项指标

单车间、单月（或全年累计）口径：

| 指标 | 算法 | 着色参考 |
|---|---|---|
| 首件一次合格率 | 有批次时 `100% − NG 批 / 总批`；无批次为「—」。判定忽略大小写，`NG` 为不合格 | 矩阵目标 95%；总览 ≥ 90% 为达标色 |
| 终检批次不良率 | `NG 批 / 检验批`。分母来自该车间台账在所选月份的批次数 | 目标 ≤ 3%；超过为危险 |
| 投诉批次 / 结案率 | 批次按**责任车间**（`dept`）归入该车间。结案率 = 有实际结案日期的批数 / 批数。无投诉时结案率为「—」 | 未结案 > 0 为关注 |
| 点检得分 | **总看板**取该责任区所选月份的得分；选「全年」取各月算术平均 | 目标 100 分。&lt; 90 严重，&lt; 100 未达标 |
| 绩效均分 | 见 5.7，先算到人再平均 | 基准 100；≥ 100 为达标色 |
| 培训人次 | 所选范围内培训记录的人次数合计 | 单月且该车间为 0 场时，总看板关注区提示「本月无培训记录」 |

全厂合计直接用全量记录计算（含未能归入某一责任区的记录），不把 6 个车间数字简单相加后冒充全厂，以免漏掉未归类记录。点检全厂均值例外：它是 6 个责任区得分的算术平均，并同时给出剔除注塑毛边后的对照值。

热力矩阵可在上述指标间切换（含投诉结案率）。色阶在**同一指标**的全部车间与月份之间相对比较：深绿最好，红色最需关注。点车间名进入该车间子工作台。

异常关注最多 9 条，优先级从高到低包括：首件合格率 &lt; 60%、点检 &lt; 90、终检批次不良率 &gt; 3%（先列最高的两个车间，其余汇总成一条）、投诉未结案（先列未结最多的三个车间，其余汇总）、点检 &lt; 100、当月无培训。点击关注项进入对应车间。

### 5.3 首件 / 巡检（`fa`）

- **注塑 / 压铸 / 五金**共用「首巡检报告」表结构：**S**＝首件、**X**＝巡检。
- **印刷**：首件与终检共用一份表，**首件区域**与 **FQC 区域**分开。
- 产品阶段仅三档：`新产品TH RUN样品`、`销售员样品`、`量产`。
- 关注零件 **100394-003**：源表逐尺寸行按「日期 + 检验员」归并为一个批次；批次内任一尺寸 NG，则该批次为 NG。
- 除该零件实测外，原型中其余首件记录是按真实零件号生成的演示数据，可被用户改掉或被正式种子替换。

NG 强制流程（页面必须可见）：

| 步骤 | 动作 | 责任 | 时限 |
|---|---|---|---|
| 1 | 判定 NG，挂红标、隔离，通知当班组长 | 检验员 | 即时 |
| 2 | 反馈 NG | 检验员（系统只记录分钟数，不推送） | 5 分钟 |
| 3 | 到场确认原因，给出临时对策与永久对策 | 生产负责人、工艺工程师 | 15 分钟 |
| 4 | 未改善或未确认 OK，不得继续生产 | 生产负责人 | 持续至放行 |
| 5 | 改善后重新首件确认，留样并录入 | 检验员 | 改善后 |

时效 KPI（只统计已填写分钟数的 NG）：

- 5 分钟反馈率 = 反馈分钟 ≤ 5 的 NG 数 / 已填反馈分钟的 NG 数。
- 15 分钟介入率 = 介入分钟 ≤ 15 的 NG 数 / 已填介入分钟的 NG 数。
- 未关闭 = 判定 NG 且状态不是「已关闭」。OK 的状态为「已放行」。

**NG 确认角色**（「NG 确认」列，改判定或阶段后立即刷新）：

- 新产品阶段（TH RUN 样品、销售员样品）：**开发工程师 + QE 工程师**。
- 量产：**工艺工程师**。
- 判定为 OK：显示「—」。

标准索引：可按关键词、类型、分类过滤 Excel / Word / 图片 / CAD 文件名。打开方式限于下载或浏览器可预览类型。

### 5.4 终检 FQC（`fqc`）

- 映射：注塑、注塑毛边、压铸、五金、涂装、印刷各一本台账。「全部」为 6 本相加，注塑与注塑毛边不合账。
- 批次不良率 = NG 批 / 检验批。件不良率 = 不良 pcs / 抽检 pcs。
- 柏拉图按**缺陷项次**：一批有两项不良，两项各计 1 次，项次合计可以大于 NG 批数。
- 缺陷描述归入固定类别（毛边/水口、旧品/设变、断裂/裂纹、尺寸不良、外观缺陷、变形、碰划伤、混料/错料、加工不良、装配/功能、涂装/印刷，其余为「其他」），供总览 TOP 使用。
- 预警：单条清查记录不良率 ≥ 20% →「终检高不良」；批次不良率 > 3% →「终检批次不良率」，在车间总览置顶。

### 5.5 投诉（`cmp`）

记录同时有两个维度：

- **投诉来源部门**（谁在投诉）：分布图按此统计。同类部门按源表归并（如 BC / LP 下的产线、铆接、附件）。
- **责任车间**（谁负责）：车间筛选、未结案预警、结案率按此归集。

闭环字段覆盖：零件、料号、问题、来源、责任车间、责任人、临时对策、原因、永久对策、计划/实际回复、计划/实际处理、计划/实际结案，以及按时回复、按时处理、按时结案（源表「是 / 否」；未填视为未回复，不计入按时分母）。

重复投诉（`repeat`＝是）在总览以「重复异常」提示，供改善立项。未填实际结案日期视为未结案。

原因文本可归入：模具、调机/参数、人员作业、来料/材料、夹治具、设备、图纸/开发、检验/管理，其余为「其他」。

### 5.6 点检（`chk`）

- 全表满分 **140**（基础项扣分 + 加分项，得分可以超过 100），目标 **100**。6 个责任区同一套表、同一套规则，一起排名。
- **注塑毛边**适用项分值：1–9 月合计 **40**，10 月起 **60**。10 月分数抬升来自适用项变多。不做折算，不因此单独一套达标线。达标仍看是否 ≥ 100。
- **两个页面的点检数字允许不同**：总看板用所选月或 1–10 月均值；车间总览与点检页用**最近一次实测分**。口径说明里必须写明，避免当成数据错误。
- 全厂均值两列并列：6 区算术平均（含毛边），以及剔除毛边后其余责任区的平均。差值用脚注说明来自适用项多少。
- 排名表、月趋势、日点检色块由得分计算得出，单元格不可直接改。

### 5.7 培训（`trn`）与绩效（`perf`）

培训路径：资料库 → 实施记录 → 考核 → 技能矩阵。技能矩阵等级为 1–4，点击切换。资料中「通用」在各车间可见。考核达标色参考平均分 ≥ 85。

绩效：

- 维度：准确率、准时率、纪律、团队协作。各条加减分规则以原型「考核方案」文案为准（漏检、报表作假、后工序投诉分档、迟到旷工、协助与 5S 等），页面需可阅读，不能只剩一个总分。
- 个人月均分 = `100 + 各月净加减分的平均`。一条记录若写了多名责任人（用 `/` 或 `、` 分隔，且为 2–3 个汉字的姓名），分数均分到这些人。
- 等级：≥ 105 为 A，≥ 100 为 B，≥ 95 为 C，低于 95 为 D。
- 排名按月均分；排名表只读。加减分明细可编辑，编辑后排名重算。
- 页面说明：个人绩效金额 = 总绩效金额 ×（个人得分 ÷ 总得分）；得分可以为负。本期展示得分与等级，不计算工资金额。

### 5.8 编辑、保存与刷新（`data` 及各表）

- 总看板、点检排名、绩效排名、图表只读。
- 首件、FQC（NG 批次与清查）、投诉、培训资料 / 记录 / 考核、绩效明细：单元格内联编辑，失焦后写入本机（localStorage，或工程等价的 IndexedDB，对用户仍是本机、可导出）。
- 枚举列用下拉：判定、状态、阶段、车间。
- 撤销：Ctrl/Cmd+Z 或「撤销」回退当前表最近的单元格编辑。
- 键盘：Tab / Shift+Tab 左右移格，Enter 下移。从表格复制的一块区域，可从起始格粘贴填入。
- 中文输入法组词期间不触发整表刷新。
- 改数字后，本页 KPI、图表、结论文案更新；表格 DOM 保持滚动位置与焦点。
- 各表可独立搜索、分页、导出当前结果 CSV。
- 全局 JSON 导出 / 导入。导入覆盖全库前提示。恢复种子数据须二次确认，并说明本地编辑会被清掉。
- 打印：隐藏侧栏与筛选等工具，主内容可读，版式适合例会（原型为 A3 横向）。

## 7. 验收（可观察结果）

1. 默认进入总看板。切换全年与 1–10 月后，六项指标、热力矩阵、点检与投诉走势随月份变化；无数据的格子是「—」。
2. 从总看板进入「注塑」后，侧栏只保留子工作台模块，横幅含负责人与 CE。总览里该车间、该月的首件合格率、投诉结案、终检不良率与总看板同一车间同一月一致。
3. 停在「全部车间」时，不能直接打开首件、FQC、投诉等录入页。
4. 打开注塑毛边：首件合格率为「—」，并有「源表未覆盖、不要当成 0%」的说明。点检处能看到适用项 40 / 60 与「含毛边 / 剔除毛边」两个均值。
5. 首件表把一条改为 NG：该行按 NG 样式显示；「NG 确认」随阶段在「开发工程师 + QE 工程师」与「工艺工程师」之间切换；OK 时为「—」。总览的 5 分钟反馈率、15 分钟介入率随之变化。5 步流程在首件或总览上可读。
6. 100394-003 的批次口径在口径说明中写明：逐尺寸归并，任一项 NG 则批次 NG。
7. FQC：切换车间后，批次、柏拉图、NG 明细只含该车间那一本台账。不良率 &gt; 3% 时总览顶部出现批次不良预警；单条 ≥ 20% 时出现高不良提示。导出 CSV 为当前筛选结果。
8. 投诉：来源分布按「谁在投诉」而不是按责任车间。未结案出现在总览异常区；填上实际结案日期后从异常区消失，结案率更新。重复投诉有单独提示。
9. 点检排名与绩效排名不能直接改单元格；改绩效明细后排名与 A/D 人数更新。总看板点检（月均或当月）与点检页「最近一次」的差异在口径说明里写清。
10. 培训页能走完资料、实施记录、考核、技能矩阵四级切换。
11. 数据页：导出 JSON，清除本机存档后再导入，编辑过的内容回来。恢复种子前有二次确认。
12. 单元格编辑后有已保存反馈。Ctrl+Z 只撤销当前表最近一次编辑。打印预览看不到侧栏和顶栏筛选。
13. 页面不出现「正在调用模型」或自动改写业务数字的入口。

验收以本规格为准。实现步骤、文件与测试见实施计划。E2E 在实现阶段再固化选择器，本规格不预设 `data-testid`。
