## 1. 目标

用户在 IPQC 点击「使用 data-hub 登录」，密码只在 data-hub 登录页输入。IPQC 拿到 data-hub 用户 `id` 后，在自己的用户表里绑定或新建本地用户，再签发 IPQC 自己的会话。

各项目认的是同一个 data-hub 用户 `id`。手机号只用于第一次把已有本地账号对上。对上之后以 `id` 为准。

成功标准：

1. 完成一次授权后，IPQC 能确定唯一的 data-hub 用户 `id`，并把它写入本地用户的 `dataHubUserId`。
2. 本地已绑定该 `id` 时，直接登录该本地用户。
3. 尚未绑定时，用规范化后的 11 位手机号对上唯一本地用户并写入绑定。
4. 手机号一条都对不上时，新建本地用户并绑上该 `id`，然后登录。
5. 手机号对上多条，或目标用户已绑了另一个 data-hub 用户时，拒绝登录，不覆盖原绑定。
6. IPQC 不保存 data-hub 密码，不把 data-hub 的 Cookie、访问令牌或刷新令牌当作自己的登录态。

## 2. 范围

### 本期做什么

- 未登录访问工作台时进入 `/login`。页面只有「使用 data-hub 登录」，没有账号、密码输入框。
- 浏览器打开 data-hub 的 `/oauth/authorize`（已登记的 `client_id`、与登记逐字相同的 `redirect_uri`、`scope=mcp:read`、`code_challenge_method=S256`、IPQC 自己的 `state`、data-hub 要求的 `resource`）。
- 回调地址为 IPQC 前端 `/login/callback`。页面把 `code`、`state` 或 `error` 交给 IPQC 服务端。
- 服务端用授权码向 data-hub `POST /oauth/token` 换票，再带访问令牌调用 `GET /api/v1/auth/me`，按第 4 节认人，然后签发 IPQC 会话 Cookie。
- 确认身份后立即丢弃 data-hub 的访问令牌和刷新令牌。数据库、日志、响应体和浏览器存储里都不保留这两段令牌。
- 顶栏提供当前用户显示名和退出。退出只清除 IPQC 会话。

### 明确不做什么

- 不修改 data-hub 的接口、页面、令牌范围和数据库。
- 不在 IPQC 登录页收集或转发密码。不用口令换票，也不调用 `POST /api/v1/auth/token`。
- 不把 data-hub 的 `admin` / `user` 复制成 IPQC 权限。自动开户的本地角色固定为 `user`。
- 不读取共享盘，不解析 Excel / CSV，不把质量台账迁入 PostgreSQL。现有 `localStorage` 台账行为保持不变。
- 不在再次登录时按新手机号重对、不更新已有本地用户的手机号、显示名和角色。
- 不改 `.github/`，不改总看板、车间子页的计算口径。
- 用户拒绝授权，或授权码换票失败：不创建、不绑定本地用户。

## 3. 目标行为

| 场景 | 现在 | 改后 |
|---|---|---|
| 打开工作台 | 直接进入总看板，无账号 | 未登录先到 `/login` |
| 登录 | 无 | 点「使用 data-hub 登录」，在 data-hub 输入密码并同意；回到 IPQC 后进入登录前要去的页面，缺省为总看板 |
| 已绑定同一 data-hub 用户 | 无本地用户 | 进入原来的本地用户。data-hub 之后改了手机号也仍是这个用户 |
| 本地已有唯一相同手机号且未绑定 | 无 | 进入该用户，并写上 `dataHubUserId`，不新建第二条 |
| 本地没有该手机号 | 无 | 新建一条本地用户。手机号是规范化后的 `loginName`，显示名是当次 `displayName`，`dataHubUserId` 是当次 `id`，角色是 `user` |
| 手机号重复，或该用户已绑定别人 | 无 | 登录失败，本地数据不变，并提示管理员 |
| data-hub 用户已停用，或登录名不是 11 位手机号 | 无 | 登录失败，不自动开户 |
| 退出 | 无 | 顶栏退出后回到 `/login`，原 IPQC 会话失效 |

## 4. 认人

`GET /api/v1/auth/me` 成功之后按顺序处理。`loginName` 先去掉空格和横线，结果必须是 11 位数字；否则拒绝本次登录，不自动开户。

| 顺序 | 条件 | 结果 |
|---|---|---|
| 1 | `status` 不是 `active` | 拒绝。提示「账号已停用」 |
| 2 | 本地已有未删除用户，其 `dataHubUserId` 等于返回的 `id` | 登录该用户。不再用手机号重对 |
| 3 | 规范化手机号对上唯一未删除用户，且该用户尚未绑定 | 写入 `dataHubUserId = id`，然后登录 |
| 4 | 手机号对上多条 | 拒绝。提示「手机号重复，请管理员处理」 |
| 5 | 对上的那条已经绑定了另一个 `dataHubUserId` | 拒绝，不覆盖。提示「该手机号已绑定其他 data-hub 用户」 |
| 6 | 一条都对不上 | 新建并登录 |

新建时若手机号或 `dataHubUserId` 与已有记录冲突，拒绝本次登录，不插入第二条。提示「账号已存在，请联系管理员」。

用户取消授权时提示「已取消授权」。`state` 与发起登录时不一致、授权码无效或过期时拒绝，提示说明失败原因，且不建户、不绑定。

## 5. 交互、会话与数据

- `/login`、`/login/callback` 与 `default-layout` 并列，`meta.public: true`。其余工作台路由未登录时跳到 `/login`，并用 `redirect` 记下原地址。
- 登录页不放密码框，也不在卡片里放失败 `el-alert`。失败文案走请求拦截器。登录相关请求的 `sessionExpiredOn401` 为 false。
- IPQC 会话是 HttpOnly Cookie，只在服务端保存令牌哈希。data-hub 的 PKCE `code_verifier` 只在回调完成前短暂保存，回调结束后删除。
- 本地用户软删。列表和认人都不使用已删除行。`phone`、`dataHubUserId` 在未删除用户中唯一。
- 接口前缀 `/api/v1`。Controller 只返回业务体，信封由全局拦截器包装。

| 方法 | 路径 | 成功时的 `data` |
|---|---|---|
| `POST` | `/api/v1/auth/data-hub/start` | `{ authorizeUrl }`。同时写下一次性 state Cookie |
| `POST` | `/api/v1/auth/data-hub/callback` | 本地用户 `{ id, phone, displayName, role, dataHubUserId }`。同时写下会话 Cookie |
| `GET` | `/api/v1/auth/me` | 同上。无有效会话时 401 |
| `POST` | `/api/v1/auth/logout` | `{ ok: true }`，并清除会话 Cookie |

失败信封的 `message` 用第 4 节的中文短句。协议或状态类失败为 401 `unauthorized`；手机号重复、绑定冲突、唯一约束冲突为 409 `conflict`。

缺少 `DATABASE_URL`、data-hub 对外地址、OAuth `client_id`、`resource` 或回调地址时，API 进程启动失败并说明缺哪一项。不回退到默认秘密。`client_secret` 仅在 data-hub 为该客户端登记了密钥时才发送。

回调地址必须与 data-hub「系统管理 → OAuth 客户端」里登记的地址逐字相同。开发环境默认 `http://localhost:5176/login/callback`。浏览器打开的授权地址走 data-hub 前端源（开发环境 `http://localhost:5175`），服务端换票和 `/api/v1/auth/me` 走 data-hub API 源（开发环境 `http://localhost:3005`）。

## 6. 验收

1. 未登录打开 `/board` 会到 `/login`。登录页看不到密码框。
2. 同意授权后进入工作台，顶栏能看到该用户显示名。IPQC 库中该用户的 `dataHubUserId` 等于当次 `/api/v1/auth/me` 的 `id`。
3. 本地已有相同 11 位手机号的唯一未绑定用户时，首次登录进入该用户并写入 `dataHubUserId`，用户表仍是一条。
4. 本地没有该手机号时，新增一条用户，手机号、显示名、`dataHubUserId` 与当次身份一致，角色为 `user`（即使用户在 data-hub 是管理员）。
5. 绑定完成后，即使用户在 data-hub 改了手机号，再次登录仍是原来的本地用户，手机号、显示名、角色不变。
6. 同一手机号有多条本地用户，或目标用户已绑定别的 data-hub 用户时，登录失败，本地数据不变。
7. data-hub 中该用户已停用，或 `loginName` 规范化后不是 11 位数字时，登录失败，不新建用户。
8. 在 data-hub 拒绝授权，或使用无效授权码时，不新建、不绑定。
9. 数据库、日志、响应和浏览器存储中不出现 data-hub 密码、访问令牌和刷新令牌。
10. 退出后 `GET /api/v1/auth/me` 为 401，再次打开工作台回到 `/login`。
11. 总看板和各车间页的原有台账仍来自本机，不因本次登录被清空或改写。
