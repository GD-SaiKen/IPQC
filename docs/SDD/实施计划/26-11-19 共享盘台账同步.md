## 文件职责

| 路径 | 职责 |
|---|---|
| `prisma/schema.prisma` | 本地用户增加刷新令牌密文、nonce、版本号；可空。退出后清空 |

| `apps/api/modules/ledger-sync/map-workbook.ts` | 把 `sheets` 映射为 `fa` / 终检 / `cmp` / 点检 / `perf` |
| `apps/api/modules/ledger-sync/data-hub-files.ts` | 调 data-hub：`GET /api/shares`、`GET /api/search/files`、`GET /api/shares/{id}/workbook`、刷新访问令牌。路径不带 `v1` |
| `apps/api/modules/ledger-sync/ledger-sync.service.ts` | 核对与正式同步；不写台账表 |
| `apps/api/modules/ledger-sync/ledger-sync.controller.ts` | 三个路由；只接受已登录用户 |
| `apps/api/.env.example` | 增加 `DATA_HUB_TOKEN_KEY`，不写真值 |
| `apps/web/src/domain/ipqc/merge-snapshot.ts` | 用快照替换源表数组，保留培训三张表 |
| `apps/web/src/views/data/index.vue` | 选择绑定、填写目录、核对、确认写入 |
| `docs/项目-业务约定.md` | 写上三个路径，并说明台账仍在本机、来源可以是共享盘同步 |

开发端口不变：Web `5176`，API `3006`。data-hub 仍用现有 `DATA_HUB_*`。

## 手工验收

前置：data-hub 已提供 `/workbook`，且该用户至少有一个 `ready` 绑定，目录内文件名符合规格第 4 节。IPQC 已配置 `DATA_HUB_TOKEN_KEY` 并应用 migration。用现有 data-hub 登录进 IPQC。

1. 打开 `/data`，选择该绑定，目录填台账所在相对路径。核对区出现每个角色一条路径和条数，此时刷新页面，台账仍是核对前的内容。
2. 确认同步。首件、终检、投诉、点检、绩效条数与核对一致。培训三张表条数不变。
3. 把终检其中一本改名后再同步，页面提示缺失，条数保持第 2 步的结果。
4. 退出后查库：该用户的刷新令牌密文字段为空。日志里搜不到 `refresh_token` 和访问令牌。
5. 在 data-hub 解除 IPQC 的授权后再同步，提示重新登录，本机条数不变。
