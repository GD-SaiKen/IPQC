## 1. 目标

全厂只有一份台账，放在服务器。已登录用户打开页面就读这同一份，改完写回服务器。浏览器不再读取、写入或删除台账键和核对范围键。

服务器从空库开始。不把现有浏览器里的台账迁进去。管理员在「数据与设置」连接 data-hub、保存核对范围后，可以立即同步，也可以等到每天的固定钟点。同步规则：

- 共享盘有、系统没有：新增。
- 两边都有且要比的字段相同：跳过。
- 两边都有但字段不同：九张表保留系统里的值，另写差异报告。点检分数没有人工编辑，改为写入共享盘的新分数，并留下差异。
- 系统有、共享盘没有：不删除。

页面上的表格使用 RevoGrid（`@revolist/vue3-datagrid`）编辑。差异不画在格子上。报告链接能打开对应页面；行还在就选中它，行已删除就显示「该行已删除」。

## 2. 范围与非目标

### 2.1 本期范围

- 九张表、点检分数、墓碑、同步配置、同步轮次和差异写入 PostgreSQL。
- 去掉台账键、核对范围键的 `localStorage` 读、写、删。页面只在内存中放本次从服务器读到的数据。
- 首件改为 Excel 一行一条后再入库。
- 管理员保存的核对范围放在服务器，立即同步和定时同步共用。
- 定时同步默认每天 06:00（Asia/Shanghai）。每个上海日历日最多自动尝试一次。
- 同一次同步的台账、墓碑和差异在一个数据库事务里提交或一起回滚。
- 首件、终检、投诉、培训、绩效的可编辑表换成 RevoGrid。
- 导出改为下载服务器当前台账。去掉 JSON 导入。
- 同一版本废弃会覆盖台账的旧同步接口。前端同一版本改完，不双写。

### 2.2 非目标

- 不把浏览器里已有的 `localStorage` 台账导入服务器，也不提供一次性 JSON 迁移。
- 不把系统里的修改回写到共享盘。
- 不在格子上标记差异，不做单元格评论。
- 不提供「取消墓碑、让已删行再次从共享盘回来」的操作。
- 不做角色管理页。是否管理员只看现有 `role === 'admin'`。
- 不改共享盘文件选择、扩展名、角色匹配和列缺失判断。
- 不做多人光标或实时推送。其他人要重新进入页面或重新读取才能看到新数据。
- 不同步秒级，也不做一天多次、按星期几的日程。定时失败后当天不自动再试。
- 不做乐观锁。同一字段以数据库里后一次成功提交的 `PATCH` 为准。
- 侧栏折叠仍可使用 `localStorage` 键 `ipqc:sidebar-collapsed`。它不是台账，也不在本文件的清除范围内。

## 3. 首发、回滚与旧数据

发布时数据库里的九张表、点检分数、墓碑和同步轮次都是空的。页面初始数据来自 `GET /api/ledger`。服务器没有行时各表为空，不调用种子数据。

新版本对下面两个键不得调用 `getItem`、`setItem`、`removeItem`：

| 键 | 旧用途 |
|---|---|
| `ipqc_wb_v2` | 整份台账 |
| `ipqc_ledger_sync_saved_selection` | 共享盘核对范围 |

因此发布不会擦掉用户浏览器里的旧台账。旧版页面若重新部署，仍能读到发布前留在本机的那一份。新版页面不显示它，也不把它上传。

没有迁移步骤，所以不存在迁移失败和重复迁移。误把旧 JSON 再导入的入口也不存在：页面没有 JSON 导入。

回滚是指把前端和 API 部署回上一版。浏览器里未删除的 `ipqc_wb_v2` 仍可供旧版使用。回滚后的旧版不读取本文件新建的 PostgreSQL 台账表。服务器上已经同步进去的行留在库里，不在回滚时自动删除。

验收见第 10 节第 8、9 条。

## 4. 数据模型

时间字段都是 `timestamptz(3)`，库存 UTC，接口用 ISO-8601 带偏移量的字符串。业务上的「日期」不是这个类型，见下文。

文本业务字段：非空字符串，默认 `''`。写入前做 Unicode NFC，并去掉首尾 Unicode 空白（`White_Space`）。纯空白变成 `''`。不把空字符串存成 `null`。超过该列最大长度时，这一次请求返回 400，不截断。清理后的文本若含 Unicode 类别 `Cc` 的控制字符（含 U+001E、换行、制表符），该次请求返回 400，`message` 指出字段名，不入库。同步过程中任一映射后的文本、工作表名或路径含这类字符时，整轮失败并回滚，原因写明字段。点检分数的 `workshop`、`month` 同样拒绝控制字符。

数字业务字段：`numeric(12,4)`，可空。请求里缺失、`null` 或 `''` 存 `null`。有值时必须是有限数字，否则 400。比较时比较库存数值，因此 `1` 和 `1.0` 相同。

日期业务字段：`varchar(32)` 文本，非空，默认 `''`。不做日期格式归一。`2026-01-02` 和 `2026/1/2` 是不同的值，也是不同的 `sourceKey` 段。

每张业务表都有：

| 列 | 类型 | 约束 |
|---|---|---|
| `id` | uuid | 主键，系统生成 |
| `sourceKey` | text | 可空。非空时在该表内唯一 |
| `sourceFile` | text | 可空 |
| `sourceSheet` | varchar(128) | 可空 |
| `sourceRow` | int | 可空。Excel 物理行号，从 1 起，含表头 |
| `createdAt` | timestamptz(3) | 非空，插入时写入 |
| `updatedAt` | timestamptz(3) | 非空，每次成功的插入或 `PATCH` 更新 |

用户修改业务字段时，不改 `sourceKey`、`sourceFile`、`sourceSheet`、`sourceRow`。请求里若带这些字段，返回 400。

页面上只用于展示、由其他列算出来的值不入库，也不参与比较。当前包括首件的「NG 确认」和终检清查的「不良率」。

### 4.2 sourceKey

只给 `fa`、`fqcNg`、`fqc`、`cmp`、`perf` 计算。培训四张表的 `sourceKey` 保持 `null`。

段清理与文本入库相同：NFC，去掉首尾 Unicode 空白，保留中间空白和大小写。日期段用清理后的原文，不改成统一日期格式。

用记录分隔符 U+001E 拼接。业务段按第 4.3 节的顺序。只要有一段是空字符串，就在这些业务段后面再追加三段，而且只追加一次：文件路径、工作表名、Excel 物理行号。不是每个空段各追加一次。进入键的每一段都已经拒绝 U+001E，因此段内不会再出现分隔符，拆开键时不会多出一段。

路径段先按 `normalizeLedgerPath`（反斜杠改斜杠、去掉首尾斜杠和首尾空白），再把这一段转成小写。因此只在路径参与键时，`品质/A.xlsx` 和 `品质/a.xlsx` 是同一路径段。工作表名保留大小写。行号用十进制整数的字符串，没有前导零。

业务段全部非空时，路径、工作表和行号不进入键。这时移动文件、重命名工作表、在上方插行，都不改变 `sourceKey`，仍视为同一条。

有空业务段时，路径、工作表或行号任一变化都是另一条。文件移动、工作表改名、上方插行都会让这条变成共享盘上的新记录；系统里的旧行保留，新行按新增插入。

同一张共享盘结果里，算出同一个 `sourceKey` 两次：这两条都不入库，各写一条「无法对应」。

示例（分隔符写成 `␟`）：

- 首件各段都有：`2026-01-02␟注塑␟PN1␟外观␟量产`。文件改名不影响这条键。
- 首件料号为空，文件 `品质/首件.xlsx`、表 `SX`、物理行 12：`2026-01-02␟注塑␟␟外观␟量产␟品质/首件.xlsx␟SX␟12`。只追加一次路径、表名和行号。有人在第 12 行上方插入一行后，这条键的行号变化，同步把它当作新记录。

## 5. 页面写入与并发

`POST` 只接受该表业务字段。未传的文本当 `''`，未传的数字当 `null`，`skill.lv` 未传当 `[]`。`sourceKey` 固定为 `null`。

`PATCH` 是部分更新：只改请求里出现的业务字段。没出现的字段保持原值。因此两个人同时改同一行的不同字段时，两边都会留下。同一字段则以后一次成功提交的事务为准，不以用户点击的先后为准。不使用版本号。后一次提交不检查 `updatedAt`。

`DELETE`：行有非空 `sourceKey` 时，在同一事务里确保墓碑存在，再删除该行。该 `sourceKey` 的墓碑已经存在时，不再插入第二条，继续删除活行，返回成功。没有 `sourceKey` 的行直接删除，不写墓碑。`id` 对应的行已经不存在时返回 404，不新造墓碑。

撤销只针对当前页面会话里已经成功保存的单元格，最多 20 步，刷新或离开页面后清空。一步是一个字段的旧值。点击撤销就用该旧值再发一次 `PATCH`。成功才出栈。失败则不出栈，格子仍显示当前值，并提示保存失败。连续撤销从栈顶逐条执行。新增行和删除行不能用这个撤销收回。

读取失败时提示错误，表格为空，不回退到种子或本机旧数据。保存失败时该格保持未保存并提示。新增或删除失败时，界面不留下那次操作。

## 6. 同步

立即同步和定时同步用同一套业务规则。读取的是服务器上已保存的核对范围，不是浏览器树上当时的勾选。

### 6.1 锁、事务和轮次

全库一把同步锁（PostgreSQL advisory lock，固定键）。拿不到锁就不读共享盘，也不改台账。

一轮的顺序：

1. 先插入一条轮次，状态为 `running`，生成 `executorId`，`leaseExpiresAt` 为当前时间加 3 分钟，并提交这一小步。定时轮次同时写下当天的 `scheduledRunDate`。这一步不改台账。
2. 尝试加锁。拿不到：仅当 `status` 仍为 `running` 且 `executorId` 仍是这一轮时，把该轮改为 `failed`，原因「已有同步正在执行」，结束。不开启台账事务。
3. 持锁读取并解析共享盘。授权失效、缺必需文件、列不匹配、解析失败或文本含控制字符：用同样的 `executorId` 条件把该轮改为 `failed`，写上中文原因，释放锁。台账、墓碑和已有差异都不改。立即同步的请求若带 `previewFiles`，实际解析集合与它相比出现新增、缺失，或同一路径的 `modifiedAt` 变化时，同样失败，原因为「共享盘文件已变化，请重新核对」。定时同步不带 `previewFiles`，按已保存范围直接读取。
4. 开启一个数据库事务，隔离级别 Read Committed。在这个事务里完成第 6.2 节的全部插入和差异。把该轮改为 `success` 的语句必须带 `status = running` 且 `executorId` 等于本轮。影响行数为 0 时，回滚整个台账事务，不得再把轮次写成 `success`。影响行数为 1 时才提交。
5. 第 4 步因语句失败而回滚后，另开一个短事务，只在 `status` 仍为 `running` 且 `executorId` 仍是本轮时把该轮改为 `failed`。影响行数为 0 表示租约已经被判为中断，保持该状态。然后释放锁。

因此不会出现「有的表已经写入、轮次却是成功」或「差异写上了、台账回滚了」。失败轮次保留，失败轮次没有差异行。

匹配到已有行时，在第 4 步的事务里对该行 `SELECT FOR UPDATE`，只读业务字段来比较，不对已有行做 `UPDATE`。并发的 `PATCH` 会等到这把行锁释放后再写入，所以同步不会盖掉编辑。若 `PATCH` 在这次 `SELECT` 之前已经提交，比较用的就是编辑后的值。

执行中的进程每 60 秒心跳一次。心跳只更新仍为 `running` 且 `executorId` 等于自己的那一行，把 `leaseExpiresAt` 延长到当前时间加 3 分钟。心跳影响行数为 0 时，该进程停止后续写入；台账事务若还开着就回滚，并释放锁，不得再提交 `success`。

分钟检查只把同时满足 `status = running` 且 `leaseExpiresAt < 当前时间` 的轮次改为 `failed`，原因「同步中断」。不按“已经跑了多久”判断。同步即使超过 30 分钟，只要心跳仍把租约留在未来，轮次就保持 `running`。进程退出后心跳停止，租约到期，锁也随连接释放，这时才允许标记中断。当天的定时名额已经用掉，不再自动开一轮。原进程若在此之后才执行 `success` 更新，因 `executorId` 条件匹配不到行，台账事务回滚，轮次保持 `failed`。

轮次字段：

| 字段 | 含义 |
|---|---|
| `runType` | `manual` 或 `scheduled` |
| `status` | `running`、`success`、`failed` |
| `message` | 失败原因；成功时为空字符串 |
| `startedAt` / `finishedAt` | 开始与结束 |
| `actorUserId` | 手动：点击的管理员。定时：当时配置上的 `savedByUserId` |
| `configVersion` | 拿到锁之后读到的配置版本 |
| `scheduledRunDate` | 仅定时有值，上海日历日 `YYYY-MM-DD`。手动为 `null` |
| `executorId` | 这一轮执行者的 uuid。心跳、失败和成功更新都要带上它 |
| `leaseExpiresAt` | 租约到期时间。只有到期后才允许把 `running` 标成中断 |
| 条数 | 新增、跳过、差异、无法对应、按删除跳过 |

`runType = scheduled` 且 `scheduledRunDate` 非空时，该日期唯一。同一天不能插入第二条定时轮次。

差异行挂在轮次上：`tableName`、`rowId`（可空）、`field`、`shareValue`、`gridValue`、`kind`、`workshop`（可空）、`month`（可空）。`kind` 为 `diff`、`unmatched` 或 `tombstone_conflict`。无法对应没有 `rowId`。点检差异没有 `rowId`，用 `workshop` 和 `month` 生成链接。值用入库后的字符串；数字用库存的规范小数文本；`null` 记成空字符串。

轮次和它的差异保留 180 天，按 `startedAt` 计算。每天的分钟检查顺带删除更早的轮次和差异。不删除台账行、点检分数和墓碑。

两个管理员同时保存配置时，各自的请求都是整份替换，不是字段合并。后一个提交成功的事务留下。`configVersion` 在每次成功保存时加 1，并记下 `savedByUserId`。正在跑的同步继续使用它加锁后已经读到的那一版；轮次上的 `configVersion` 就是这一版。下一次同步才使用新配置。

### 6.2 对应规则

1. 首件按 Excel 一行解析成一行，不再把同一天同一检验员收成一条。
2. 映射字段并计算 `sourceKey`。
3. 共享盘上同一个键出现两次：都不入库，各写一条 `unmatched`。条数按共享盘行数计。
4. 该键已有墓碑：不新增，只累计「按删除跳过」。
5. 墓碑和一条仍存活的相同键同时存在：不改活行，写一条 `tombstone_conflict`。
6. 系统没有这个键：插入，分配新 `id`，写上来源位置。
7. 系统有这个键，且要比较的业务字段都相同：跳过。
8. 系统有这个键，但有字段不同：不改系统行。每个不同字段写一条 `diff`。
9. 系统有而共享盘没有：不删除，也不写差异。

要比较的字段是第 4.1 节该表的业务列，含 `skill` 以外各表的数字列。不比较 `id`、`sourceKey`、来源位置、`createdAt`、`updatedAt`，也不比较只在页面上计算的列。文本按入库后的字符串比。数字按 `numeric` 比，两边都是 `null` 视为相同。

点检分数只由同步写入。点检页只读，不提供编辑控件，也没有点检分数的 `POST`、`PATCH`、`DELETE`。因为没有人工修改要保护，共享盘值与库存不同时，把库存更新为共享盘值，并写一条 `diff`：`tableName` 为 `checkScores`，`rowId` 为空，`field` 为 `score`，`gridValue` 是更新前的库存，`shareValue` 是共享盘值。系统没有该车间和月份则插入，不写 `diff`。数值相同则跳过。共享盘没有的车间和月份不删除。链接用车间和月份，不依赖行 `id`。

培训四张表在同步中不读、不写、不比较。

同一份共享盘重复跑一轮成功同步时，已存在且值相同的行只增加跳过条数，不产生第二行。

### 6.3 定时与授权

全厂一行配置：`shareId`、`selectedEntries`、`excludedPaths`、`hour`、`minute`、`savedByUserId`、`configVersion`、`updatedAt`。默认钟点 06:00。小时 0–23，分钟 0–59，时区 Asia/Shanghai。

保存配置时，当前管理员必须已经连接 data-hub，否则 400，配置不变。`selectedEntries` 和 `excludedPaths` 各最多 500 条，超出 400。

解除 data-hub 连接不删除配置，也不改 `savedByUserId`。之后的定时同步仍会尝试，并失败，原因「授权已失效」。该管理员重新连接后，下一次定时或立即同步继续使用这份配置和他的新令牌，不必重新保存范围。另一位管理员重新保存配置后，`savedByUserId` 改为后者，此后用后者的令牌。

每个上海日历日最多一条定时轮次，不论成功还是失败。分钟检查的规则：

- 当天已经有定时轮次：不再启动。
- 当前时间已到钟点，且当天还没有定时轮次：插入定时轮次并执行。进程在钟点时没开着的，启动后用同一条件补一次。
- 定时失败，包括拿不到锁、授权失效、解析失败、超限和中断：当天不再自动重试。管理员可以立即同步。立即同步不写入 `scheduledRunDate`，不占用当天的定时名额。
- 未保存配置：到点仍插入一条失败轮次，原因「尚未配置同步」，以免同一天每一分钟都再试一次。

## 7. 页面

差异链接的查询参数统一为：

| 目标 | 地址 |
|---|---|
| `fa` | `/fa?rowId=<uuid>` |
| `fqc`、`fqcNg` | `/fqc?rowId=<uuid>&table=<fqc 或 fqcNg>` |
| `cmp` | `/cmp?rowId=<uuid>` |
| `perf` | `/perf?rowId=<uuid>` |
| `mat`、`trn`、`exam`、`skill` | `/trn?rowId=<uuid>&table=<表名>` |
| 点检分数 | `/chk?workshop=<车间>&month=<月份>` |

打开带 `rowId` 的页面时，先请求该行。200 就选中该行，不改变格子的颜色或文案。404 就在页面顶部显示「该行已删除」，表格仍显示当前数据，不选中任何行。不静默丢掉这个参数。点检链接找不到该车间和月份时，同样显示「该记录已删除」。

「数据与设置」只对管理员展示已保存范围、钟点、轮次列表和某一轮的差异。差异含表名、字段、共享盘值、系统值、链接。`unmatched` 没有链接。

JSON 导出是当前服务器台账，包含九张表的行（`id`、`sourceKey`、来源位置、时间、业务字段）、以及点检分数。不包含墓碑，不包含轮次和差异。某表已达 20000 行时仍允许导出该表现有行。页面不提供 JSON 导入。

CSV 按一张表导出该表全部行，不受当前搜索框过滤。编码为 UTF-8 带 BOM，逗号分隔，符合 RFC 4180。第一行是该表页面上的中文列名，随后是业务列。`skill.lv` 用英文逗号连接的数字放在一个单元格里。不导出 `id` 和 `sourceKey`。

车间筛选和看板月份只留在本次会话内存中。工具栏保留搜索、新增、删除、撤销和导出 CSV。搜索只过滤当前已经读入内存的全量。新增会使某表超过 20000 行时，接口返回 409，页面不改用种子凑数。

## 8. 接口

响应信封仍按 `docs/项目-业务约定.md`。下面只写成功时的 `data`。

`GET /api/ledger` 是全量快照，不使用分页信封。`data` 里九张表各是一个数组，`checkScores` 是 `{ list }`，没有 `page`、`pageSize` 和 `total`。写入上限保证这份快照不会被截断。

分页信封 `{ list, total, page, pageSize }` 只用于请求里带 `page` 的列表：同步轮次，以及某一轮的差异。`page` 从 1 开始，`pageSize` 默认 10，最大 100，超出 400。这两处排序固定，不接受客户端改排序字段。已有的共享盘列表和目录列表继续用它们原来的分页，不改成这份快照。

### 8.1 迁移

本版本起生效，没有并行兼容期。前端在同一版本改为只调用新路径。

| 旧路径 | 本版本 | 说明 |
|---|---|---|
| `POST /api/ledger-sync` | 410 Gone，`msg` 为 `gone`，`message` 为「请使用立即同步」 | 旧行为会覆盖台账，不能继续留用 |
| `POST /api/ledger-sync/preview` | 保留，只读 | 不写台账 |
| `POST /api/ledger-sync/scope` | 保留，只读 | 不写台账 |
| `GET /api/ledger-sync/shares` 与 `.../entries` | 保留 | 选择文件 |
| 无 | 新增第 8.2 节 | 台账与同步配置 |

`rootPaths`、`rootPath` 不再接受。传入则 400。

### 8.2 路径

| 方法 | 路径 | 谁 | `data` |
|---|---|---|---|
| `GET` | `/api/ledger` | 已登录 | 全量快照，不是分页列表。`{ fa, fqc, fqcNg, cmp, perf, mat, trn, exam, skill, checkScores }`。前九个是行数组。`checkScores` 是 `{ list: [{ id, workshop, month, score, updatedAt }] }`，没有 `total` / `page` / `pageSize` |
| `GET` | `/api/ledger/:table/:id` | 已登录 | 一行。404 表示没有或已删除 |
| `POST` | `/api/ledger/:table` | 已登录 | 创建后的行 |
| `PATCH` | `/api/ledger/:table/:id` | 已登录 | `{ id, updated: true }` |
| `DELETE` | `/api/ledger/:table/:id` | 已登录 | `{ id, deleted: true }` |
| `GET` | `/api/ledger/export` | 已登录 | 第 7 节的 JSON 文档 |
| `GET` | `/api/ledger/:table/csv` | 已登录 | 第 7 节的 CSV 文件 |
| `GET` | `/api/ledger-sync/config` | 管理员 | 配置。未保存时各选择为空、钟点为 06:00、`configVersion` 为 0 |
| `PUT` | `/api/ledger-sync/config` | 管理员 | 保存后的配置 |
| `POST` | `/api/ledger-sync/run` | 管理员 | 成功时为该轮摘要。拿不到锁时 409，`message` 为「已有同步正在执行」 |
| `GET` | `/api/ledger-sync/runs?page&pageSize` | 管理员 | 轮次摘要，按 `startedAt` 降序 |

`:table` 不是九张表之一时 400。未登录 401。非管理员调用配置、立即同步和轮次接口时 403。

## 10. 验收

1. 手动同步与定时同步同时触发时，只有一个台账事务提交。另一个请求或轮次得到「已有同步正在执行」，台账行数不变。
2. 同步事务中途任一表写入失败时，九张表、点检分数、墓碑和本轮差异都与失败前一致，只多一条 `failed` 轮次。
3. 定时同步失败后的下一分钟，以及当天剩余时间，都不再发起定时同步。管理员的立即同步仍可执行。
4. 两个管理员同时保存配置后，库里只有一份配置；`configVersion` 和 `savedByUserId` 属于后提交成功的那一次。其后一轮同步的 `configVersion`、`actorUserId` 能对上当时用的那一版。
5. 两个用户同时 `PATCH` 同一行的同一字段时，后提交成功的值留下。同时 `PATCH` 不同字段时，两个字段都留下。
6. 对同一份共享盘连续成功同步两次时，第二次不新增重复行，相同行计入跳过。
7. 差异链接指向的行已被删除时，页面显示「该行已删除」，不出现空白异常，也不选中其他行冒充。
8. 发布前浏览器已有 `ipqc_wb_v2` 和 `ipqc_ledger_sync_saved_selection`。发布后刷新，页面只显示服务器数据；未同步时为空，不是种子。这两个键的字节与发布前相同。
9. 把前端和 API 部署回上一版后，旧页面能读到第 8 条里那份未改动的本机台账。
10. 新版本代码路径对这两个键不调用 `getItem`、`setItem`、`removeItem`。页面没有 JSON 导入。
11. `POST /api/ledger-sync` 返回 410。`preview` 和 `scope` 仍不写台账。
12. 普通用户不能保存同步配置，也不能立即同步。
13. 首件一份多行 Excel 会变成多条系统记录。料号为空的行，其 `sourceKey` 只追加一次路径、工作表和行号。
14. 删除一条有 `sourceKey` 的行后再次同步，该行不会回来。
15. 解除 data-hub 连接后，配置还在；定时轮次失败且原因是授权已失效。该管理员重新连接后，下一次同步不再要求先重新保存范围。
16. 同步每 60 秒心跳、持续超过 30 分钟时，轮次仍是 `running`。心跳停止且 `leaseExpiresAt` 已过之后，分钟检查才把它改为 `failed`，原因是「同步中断」。原执行者随后再提交 `success` 时更新行数为 0，台账事务回滚，轮次保持 `failed`。
17. `GET /api/ledger` 的 `data` 不含 `page`、`pageSize`、`total`。九张表是数组，`checkScores` 只有 `list`。
18. 点检页没有编辑入口。对点检分数没有 `POST`、`PATCH`、`DELETE`。共享盘分数变化时，库存改为新分数，并留下差异。
19. 任一文本字段含 U+001E 时，保存返回 400，该值不入库。同步遇到这种单元格时整轮失败，台账与失败前一致。
20. 同一 `sourceKey` 已有墓碑、同时又有一条活行时，删除该活行返回 `{ id, deleted: true }`。活行消失，墓碑仍只有一条。
