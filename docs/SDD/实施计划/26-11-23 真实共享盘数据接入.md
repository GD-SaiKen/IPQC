# 真实共享盘数据接入实施计划

> **For agentic workers:** 使用 `executing-plans` 在当前会话逐项实现；也可由用户选择 `subagent-driven-development`。以复选框跟踪任务，先读规格与本计划，先写能复现真实结构的测试再实现。

**Goal:** 勾选真实共享盘路径并保存后，自动解析指定业务工作表、同步服务器台账、展示逐文件结果，并让终检指标使用真实受检批次。

**Architecture:** 复用现有 NestJS、PostgreSQL、Prisma 和分钟调度器，不增加 Redis、SMB 客户端或 Excel 字节副本。保存配置时在同一事务内创建带配置快照的持久任务；后台领取任务，顺序处理文件、只分页读取所需工作表。模板解析产出业务事实与真实来源，终检全部受检事实独立存储并计算聚合，NG明细继续走现有编辑与差异保护。

**Tech Stack:** TypeScript、NestJS 11、Prisma 6、PostgreSQL、Vue 3、Element Plus、Pinia、现有 Vitest、pnpm 9.15.0。

**Spec:** [真实共享盘数据接入](../规格文档/26-11-23%20真实共享盘数据接入.md)。

## 全局约束

- 只调用 Data Hub 已有 OAuth 只读接口，不直连SMB、不回写源文件、不修改 `.github/`。
- 保留工作区当前已有页面、绑定助手、组件和测试改动。执行前重新查看差异；不把这些修改重置掉。
- 第一批解析三本首巡检汇总、六本终检/印刷履历、投诉、清查、点检月汇总、绩效。重点零件横向尺寸报告列为可见的待支持模板，不与年度汇总重复累计；标准、培训先列候选来源。
- 培训四张表、点检标准业务表不自动写入。佛山注塑、毛边新旧点检及重复副本不自动归并。
- 人工编辑冲突及删除标记沿用现有规则；迁移不得删除现有台账、重写既有 sourceKey 或自动执行清理脚本。
- 保存配置成功与同步成功分开呈现；全部失败不能显示成功，部分失败必须可见。
- 所有新前端测试放 `apps/web/src/__test__/` 镜像路径；后端测试放 `apps/api/__test__/` 镜像路径。
- 不把真实员工姓名、绩效事件和整份源表提交为测试夹具。使用同结构的脱敏小样。
- 行数指清单区域行数或有效记录数时明确区分；不截断后宣称成功。

## 重点审查

1. 重复列名、复检和末件区域可能覆盖原始检验字段：任务2测试相同标题出现在不同列区，初判NG且终判OK仍保留初判。
2. 同日同品号可能有多次检验：任务3测试两条不同时间/工单的记录都入库，无稳定身份的记录可见报错，不能默默合并。
3. 文件在分页期间被Excel保存：任务1/5测试前后元数据变化，本文件不提交混合版本，可重试。
4. 同步时再次保存配置或多实例抢任务：任务4测试旧任务仍读自己的配置快照，数据库只允许一个有效执行者，失去租约不能提交。
5. 单个文件读到一半失败或授权失效：任务5测试该文件保留上次成功数据，文件结果可见；授权错误不作为“不支持模板”吞掉。

## 文件与接口边界

| 文件 | 职责 |
|---|---|
| `apps/api/modules/ledger-sync/data-hub-client.ts` | 导出工作表清单、单页、元数据读取；保留旧调用兼容 |
| `apps/api/modules/ledger-sync/source-templates.ts` | 识别业务工作表与区域，不以扩展名或第一张表决定业务角色 |
| `apps/api/modules/ledger-sync/parse-source-sheet.ts` | 分区表头、日期、判定、数值解析与逐行诊断 |
| `apps/api/modules/ledger-sync/map-workbook.ts` | 将模板解析结果接到现有业务快照，保留兼容路径 |
| `apps/api/modules/ledger-sync/share-snapshot-rows.ts`、`sync-db-apply.ts` | 真实来源与批量增量写入，人工差异保护 |
| `prisma/schema.prisma`、`prisma/migrations/<时间戳>_real_source_sync/migration.sql` | 持久任务快照、逐文件状态、源版本状态、全部终检受检事实 |
| `apps/api/modules/ledger-sync/ledger-sync.service.ts`、`ledger-sync-tick.service.ts` | 保存入队、后台领取、执行、重试与定时触发 |
| `apps/api/modules/ledger/ledger.service.ts` | 返回真实终检聚合，不把全部受检事实下发到页面 |
| `apps/web/src/api/ledger-sync.ts`、`apps/web/src/views/data/index.vue` | 保存即启动、任务轮询、逐文件结果、重试 |
| `apps/web/src/api/ledger.ts`、`stores/ipqc.ts`、`domain/ipqc/fqc.ts`、`kpi.ts` | 服务器终检聚合替换空册壳依赖 |

共用类型在 `apps/api/modules/ledger-sync/source-types.ts`：

- `SourceRef = { shareId: string; path: string; sheet: string; row: number; region: string; parserVersion: string }`。
- `SourceDiagnostic = { source: SourceRef; code: string; message: string }`；不把整个原始单元格数组写日志。
- `SourceSelection = { path: string; kind: 'file' | 'directory'; role?: LedgerRole; template?: LedgerTemplate }`，兼容已有显式绑定。
- `SheetPlan = { name: string; template: string; regions: string[]; year: number; workshop?: string }`。
- `ParsedSourceRow = { table: SourceKeyTable | 'fqcInspection' | 'checkScore'; fields: Record<string, unknown>; source: SourceRef; identity: string }`。
- `ParsedFileResult = { rows: ParsedSourceRow[]; diagnostics: SourceDiagnostic[]; declaredRows: number; readRows: number; validRows: number; skippedRows: number }`。先按文件暂存解析结果，验证完整性后入库，不累计无关工作表。
