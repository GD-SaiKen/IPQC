- 依据：`docs/SDD/规格文档/26-11-21 服务器台账与定时同步.md`、`docs/SDD/规格文档/26-11-21 共享盘文件选择与可见解析.md`
- 替换口径：同步必须先解析成功、同步对比的是解析后的看板行、预览里「无效/未识别」会挡住入库

## 1. 目标（你要的四步）

| 步骤 | 做什么 | 不做什么 |
|---|---|---|
| 选文件 | 勾选目录或文件，保存核对范围 | 不读单元格、不入库 |
| 同步 | 让 data-hub 把范围内文件的**原始 Excel** 收进它的对象库，并与**上次收进来的原始文件**对比 | 不要求角色识别成功；不改看板九张表；IPQC 不再存第二份字节 |
| 解析 | IPQC 只读 data-hub 已入库的原始文件，按角色映射成业务行 | 不再次访问共享盘 |
| 入看板 | 解析成功的行写入首件、终检、投诉、绩效、点检等 | 解析失败的文件留在原始库，看板保持上次成功结果 |

保存核对范围之后就可以点同步。同步按钮不看「已解析」数量。

同步对比的对象是原始文件（路径、大小、修改时间、内容哈希），不是看板里人工改过的格子。

## 2. 存储放哪里（建议）

**原始 Excel 只在 data-hub 存一份。各业务系统不再各存一份字节。**

上一版草案把对象放在 IPQC，是为了不把看板编辑写进 data-hub。那会让每个要用共享盘的系统再复制一遍文件。文件副本应集中，业务结果仍分散。

| 放什么 | 放哪里 | 原因 |
|---|---|---|
| 文件字节、路径、大小、修改时间、内容哈希 | **data-hub + MinIO** | 全厂一份。IPQC、以后别的系统都读这一份，不再各自从共享盘拖一遍、也不各自占一块盘。 |
| 谁订了哪些路径、解析状态、看板行、人工修改、差异 | **各业务系统（IPQC）** | 这些是本系统的口径。data-hub 不知道「首件一行怎么进看板」。 |
| 不存原始、每次从共享盘现读现解析 | 不采用 | 规则一变或共享盘抖动，每个系统都要重扫；也无法回答「上次收进来的和现在是不是同一份」。 |
| 同步时把每个单元格写入 SQL | 不采用 | 宽表会把体积放大很多，而且不是原件。需要格子时从已存的文件再投影。 |

data-hub 因此多一件事：在现有「列目录 / 读表」之外，按调用方给出的路径把**未改过的文件字节**固化进对象库。这是原件冷藏，不是预制菜。

预制菜指：data-hub 按 IPQC 的角色把表切成首件、终检、投诉等业务行，调用方只加热上桌。本期不做。角色、列映射、看板、人工修改仍在各业务系统。data-hub 不解释台账角色，也不保存看板。

### 2.1 推荐形态

- **data-hub 的 MinIO**：文件字节，键用内容哈希，同一份文件不存两遍。
- **data-hub 的文件登记表**：共享盘 id、相对路径、文件名、大小、修改时间、哈希、对象键、最近同步时间。
- **IPQC**：只存「我订了哪些路径」以及解析结果（现有看板表）。解析时向 data-hub 要已入库文件或它的表投影，不在 IPQC 再落一份 xlsx。

数据量大时：

1. 只固化各系统声明过的路径，不把整个共享盘拷进 MinIO。
2. 同步先比大小和修改时间；没变则跳过。变了再哈希，哈希相同不写新对象。
3. 多个系统订同一路径时，对象只加一次引用，不复制字节。
4. 各系统解析按文件进行；解析失败不删 data-hub 里的原件，也不改其它系统的看板。

## 3. 与现行为的差别

| 现在 | 改后 |
|---|---|
| 核对解析时读表并尝试映射，失败则文件标无效 | 核对只展开范围、列出将要同步的文件，不解析 |
| 「立即同步」要求至少一份已解析，且对比解析后的行 | 「同步原始文件」只要范围内有文件即可；对比原始文件元数据 |
| 未识别、缺角色、单文件读失败会挡住整批 | 这些文件仍入库；解析阶段单独标失败原因 |
| 文案「将写入本机」 | 同步写入 data-hub 原始库；解析成功才出现在 IPQC 看板上 |

定时同步只跑「同步原始文件」。解析由管理员手动触发，或在原始文件有新增/变更后再自动排一次解析。默认定时任务不直接改看板。

## 4. 页面

「数据与设置」分成三块，互不禁用：

1. **保存选择**：与现在相同，写入服务器上的核对范围。
2. **同步原始文件**：把已保存范围交给 data-hub 固化。结果列出每个文件：新增、未变化跳过、已更新、读取失败。不要求解析成功。
3. **解析入库**：只处理 data-hub 里已有、且 IPQC 尚未解析或原件已更新的文件。成功写入看板；失败留在 IPQC 的解析记录里，可单文件重试。

看板页仍只读、只改解析后的业务表。

## 5. 本期不做

- 不在 IPQC 再存一份 Excel 字节。
- 不把全部单元格落成 SQL 宽表。
- 不把看板上的修改回写原始文件或共享盘。
- 不在本草案确认前改代码。

## 6. 验收（确认后才实现）

- 只保存目录、不点解析，同步仍让 data-hub 把目录内 xls/xlsx 收入原始库，IPQC 看板行数不变，IPQC 磁盘上没有这些 xlsx。
- 同一文件大小与修改时间未变时，再次同步不重新下载。
- 文件名对不上角色时，原始库有记录，解析结果为「未识别」，看板不新增行。
- 解析成功后，对应看板出现新行；解析失败不删除已有看板行。
- 看板上改过的单元格，在仅同步原始文件时不被覆盖。
