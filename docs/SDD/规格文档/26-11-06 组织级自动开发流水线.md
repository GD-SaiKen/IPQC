# 组织级自动开发流水线

| 项 | 内容 |
|---|---|
| **状态** | 已实现（IPQC 已接中心仓库薄触发器） |
| **确认日期** | 2026-11-06 |
| **历史** | 初版见 `docs/superpowers/specs/2026-11-05-auto-dev-pipeline-design.md` |

## 1. 范围

### 本期做什么

1. 将 `IPQC` 置于 `GD-SaiKen` 组织下，保留 Issue、标签与 Workflow 历史。
2. 新建组织中心仓库 **`GD-SaiKen/auto-dev`**，集中维护可复用 Workflow、Kimi Prompt、安装与执行 Action。
3. 业务仓库（含 IPQC）仅保留 **5 个薄触发器**，通过 `workflow_call` 调用中心实现；其他组织仓库复制接入模板即可使用。

### 明确不做什么

- 不建设 GitHub App 常驻监听（超出当前需求）。
- 不在中心仓库存放业务仓库的 `LLM_API_KEY`。
- 不自动合并非 `auto/` 前缀分支的 PR；不修改 `.github/` 的 Agent 提交。
- 不对 fork PR 运行带模型凭据的评审。
- 不声称在无 `LLM_API_KEY` 时已完成真实模型端到端验证。

## 2. 目标行为

| 场景 | 改前 | 改后 |
|---|---|---|
| 多仓库维护流水线 | 每仓复制完整 `.github/`，易分叉 | 中心统一升级，业务仓 5 个 YAML |
| 方案入口 | 分散 | 打开 Issue 即开发；`proposals/*.md` 先出方案再开发 |
| 开发 | 人工 | `auto-develop` → `auto/` 分支 PR。大改动为草稿 PR |
| 评审 / 合并 | 人工 | 非草稿走 `auto-review` → Approve 且检查通过则 `auto-merge`；打回则 `auto-fix`（最多 3 轮） |
| Secret | 可能散落 | 各业务仓自有 Secret，显式传入中心 Workflow |

## 3. 架构与调用链

```text
GD-SaiKen/auto-dev
  .github/workflows/auto-*.yml       # workflow_call
  .github/prompts/*.md
  .github/actions/setup-kimi/
  .github/actions/run-prompt/
  examples/consumer/.github/workflows/

GD-SaiKen/IPQC（及他仓）
  .github/workflows/auto-*.yml       # 事件 + 参数 + Secret + 中心引用
```

- 业务仓接收 `issues` / `push` / `pull_request` / `workflow_dispatch`。
- `GITHUB_TOKEN`、Secrets、Variables 均属业务仓。
- develop → review → fix/merge 经业务仓内 **`workflow_dispatch` 显式调度**，避免 `GITHUB_TOKEN` 二次事件抑制。
- 中心 Prompt 经 `run-prompt` 的 `github.action_path` 读取，业务仓无需自带 Prompt 文件。

## 4. 安全与交互边界

| 护栏 | 说明 |
|---|---|
| 最小权限 | develop / review / fix / plan 需要 `actions: write` |
| 提交即开发 | 新 Issue 直接进入 `auto-develop`。跨功能、对外接口、权限或数据结构的改动只开草稿 PR |
| 开发约束 | 中心 `agent-contract.md` 在开发、修复、评审时拼进提示词；业务仓不复制通用规范 |
| 自修改防护 | Prompt + Workflow 禁止改 `.github/` |
| 合并闸口 | 仅 `auto/` 分支 + bot 对当前 head SHA 的 Approved |
| 修复上限 | 自动修复最多 3 轮 |
| 版本引用 | 默认 `@main`；生产可钉 tag / SHA |

## 5. 涉及文件

| 仓库 | 路径 |
|---|---|
| IPQC | `.github/workflows/auto-*.yml`、`README.md`、`proposals/` |
| 中心 | `GD-SaiKen/auto-dev` 全文（不在本仓维护） |

## 6. 验收

1. IPQC 仓库 5 个 Workflow 在 Actions 页为 active。
2. 薄 Workflow 引用 `GD-SaiKen/auto-dev/.github/workflows/auto-*.yml@main`（或团队钉死的版本）。
3. 无 `LLM_API_KEY` 时静态校验可通过，文档不声称 E2E 模型闭环已验。
4. README 描述流程、Secret、打开 Issue 即开发，以及中心仓库链接。
5. 迁移后 `origin` 指向 `GD-SaiKen/IPQC`，Issue 历史可访问。
