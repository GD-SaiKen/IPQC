# 台账文件绑定

- 日期：2026-11-21
- 状态：已确认，实施中
- 确认日期：2026-11-21
- 范围：共享盘同步改为「角色 + 路径 + 列模板」绑定，核对与同步只读这些绑定
- 依据：`docs/SDD/规格文档/26-11-21 共享盘文件选择与可见解析.md`、`docs/SDD/规格文档/26-11-19 共享盘台账同步.md`、`docs/SDD/规格文档/26-11-21 服务器台账与定时同步.md`
- 替换口径：用文件名猜测台账角色、勾选目录后把目录内每个文件拿去对文件名、同一角色多条路径按打分留下一条

## 1. 目标

管理员在「数据与设置」里为每种台账指定共享盘上的一个文件，并带上该角色对应的列模板。保存之后，核对和同步只打开这些文件。列对得上就写入服务器台账；列对不上或读失败，只标记这一条，其余绑定照常处理。

目录里其余 Excel 不参与识别，也不再出现在「未解析」里。

## 2. 绑定是什么

一条绑定三列：

| 列 | 含义 |
|---|---|
| 角色 | 现有台账角色之一（首件、终检、投诉、绩效、点检排名等） |
| 路径 | 相对共享盘根的文件路径，只允许文件，不允许目录 |
| 列模板 | 由角色决定，保存时一并写入，供解析使用 |

角色与列模板一一对应，页面上选定角色后模板跟着显示，不能另选一套对不上的模板。

| 角色 | 列模板 |
|---|---|
| 重点零件首件、注塑首件、注塑毛边首件、压铸首件、五金首件 | 首件表 |
| 印刷品质履历 | 印刷履历（首件表 + 终检表） |
| 注塑终检、注塑毛边终检、压铸终检、五金终检、涂装终检 | 终检表 |
| 不良品清查 | 清查表 |
| 零件投诉 | 投诉表 |
| 点检排名 | 点检得分表（月份、车间、得分） |
| 点检标准 | 点检标准表（只确认文件可读，仍不把项目行写入看板） |
| 绩效 | 绩效表 |

同一角色只保留一条绑定。注塑毛边首件可以不绑。其余角色没绑时，核对里提示缺项，不阻止同步已绑且解析成功的文件。

## 3. 页面

文件树仍用于浏览共享盘。只有勾选**单个文件**才能成为绑定。勾选目录不产生绑定，也不递归把子文件送去识别。

勾选文件后为该文件选择角色。底部列出已绑定的行：角色、路径、列模板。保存写入服务器上的同步配置，全厂一份。

核对结果只列出绑定：

| 状态 | 含义 |
|---|---|
| 已解析 | 文件读成功，列与模板一致 |
| 无效 | 文件不存在、读失败，或列与模板不一致 |
| 重复 | 同一角色绑了两个路径（保存时应已被拦住；若配置里出现则阻止同步） |

不再为范围内未绑定的文件生成「未识别」「不支持」行。摘要改为「已绑定 N 个，已解析 M 个，解析失败 K 个」。

## 4. 同步

立即同步和定时同步都只读配置里的绑定路径，向 data-hub 取这些文件的表，按该条的列模板映射。

- 模板解析成功：按现有规则增量写入（新增、相同跳过、不同记差异、点检分更新）。
- 某一条解析失败：这一条不写入；其它成功的绑定仍写入；失败原因留在该次核对或该轮记录里。
- 未绑定的角色：不删除服务器上已有的对应行。
- 培训四张表仍不由共享盘同步修改。

## 5. 本期不做

- 不按文件名恢复角色识别，也不再按「2026 年」「AI 文件夹」等路径打分取舍。
- 不把整个目录扫进核对结果。
- 不新增「首（巡）检验报告」散页的归批模板。要进看板时，仍须把汇总后的那一个文件绑到对应角色。
- 不引入模型代为挑文件或抽数。
- 不改看板计算公式，不改 data-hub。
- 原始文件另行入库（见同日《原始入库与解析分步》草案）不在本期。

## 6. 绑定配置（保存与运维）

在共享盘树中勾选**单个文件**、为每条指定角色，点「保存选择」后写入服务器（全厂生效）。API **不在**启动时静默写配置。

运维可选：`pnpm apply:ledger-bindings` 从 `scripts/data/ledger-sync-bindings.example.json` 写入数据库；`--force` 覆盖已有绑定。

## 7. 验收

- 只勾选目录、不指定角色时，不能保存出绑定；同步不读取该目录下的文件。
- 为一个文件指定「注塑终检」并保存后，核对与同步只请求这一条路径，并用终检表模板解析。
- 把文件名改成不含「2026年」「品质履历」的名字，只要绑定路径仍指向该文件且列符合终检表，仍能解析入库。
- 点检排名文件缺少月份、车间或得分时，该条为无效，其它已解析绑定仍可同步。
- 同一角色绑定两个文件时不能保存；已存在的重复配置不能开始同步。
- 未绑定「注塑首件」时，提示缺项，已绑定且解析成功的投诉、绩效等仍写入服务器。
