### 5. 一轮同步的锁、事务和租约

- [ ] 先写 `apps/api/__test__/modules/ledger-sync/sync-run.test.ts`，假 Prisma 记录调用顺序：
  - 先插入 `running` 和 `executorId`，`leaseExpiresAt` 约为现在加 3 分钟，此时没有台账写入。
  - 拿不到 advisory lock：该轮 `failed`，原因「已有同步正在执行」，不开启台账事务。
  - 解析失败：不调用台账事务，轮次 `failed`，更新条件含本轮 `executorId`。
  - 成功：`$transaction` 里包含 `apply` 所需的插入、差异，以及 `success` 更新。`success` 的 `where` 含 `status: running` 与本轮 `executorId`。假客户端若让该更新影响 0 行，则事务回滚，轮次保持 `failed`。
  - 事务中途抛错：回滚后只把仍为 `running` 且 `executorId` 匹配的轮次改成 `failed`。
  - 心跳只延长匹配 `executorId` 的 `running` 行。影响 0 行时不再提交事务。
  - 租约未过期时，分钟检查不把 `running` 改成 `failed`。租约已过才写成「同步中断」。
- [ ] 看测试失败后，再写 `sync-run.ts`。锁用 `pg_try_advisory_lock` / `pg_advisory_unlock`，固定 64 位键。心跳间隔 60 秒，不在单测里真实等待。
- [ ] `POST /api/ledger-sync` 返回 410，`msg` 为 `gone`，`message` 为「请使用立即同步」。不读共享盘。
- [ ] `POST /api/ledger-sync/run` 调用 `sync-run`。未保存配置时 400，留下 `failed` 手动轮次。拿不到锁时 409。业务失败时 400，台账与失败前一致。

## 手工验收

前置：已应用 migration。至少有一名 `role` 为 `admin` 的用户，并已连接 data-hub。共享盘范围按文件选择规格保存到服务器配置。浏览器里事先已有 `ipqc_wb_v2`。

1. 两个已登录用户打开 `/fa`，看到同一份服务器数据。未同步前表格为空，不是种子。
2. 在开发者工具里看 `ipqc_wb_v2` 和 `ipqc_ledger_sync_saved_selection`，刷新前后字节不变。
3. 管理员立即同步。首件按 Excel 行拆开。再同步一次，不出现重复行。
4. 在页面改一个已同步字段后再同步，该字段仍是页面上的值，`/data` 出现差异链接，打开后选中该行。
5. 删除该行后再同步，行不回来。打开旧的差异链接，页面显示「该行已删除」。
6. 把定时钟点改到当前分钟附近，看到当天只有一条定时轮次。让解析失败，下一分钟不再自动跑。立即同步仍可点。
7. 普通用户打开配置接口得到 403。`POST /api/ledger-sync` 得到 410。
8. 点检页不能改分数。共享盘分数变化后再次同步，页面显示新分数。
9. 在一个文本单元格粘贴含分隔符 U+001E 的字符串，保存失败，刷新后该值不在。
