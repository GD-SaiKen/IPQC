## 1. 目标

登录 IPQC 的人，用自己在 data-hub 里已经绑好、状态为 `ready` 的共享盘，把品质台账 Excel 抽成工作台正在用的那套数据，写入本机。密码和 SMB 账号只留在 data-hub。

成功标准：

1. 未在 data-hub 绑好共享盘的人，IPQC 不提供填写 SMB 账号密码的入口，并说明要去 data-hub 完成绑定。
2. 每个台账角色在所选共享盘上只对上一个路径时，同步得到一份完整快照；本机在用户确认后才覆盖对应表。
3. 路径对上 0 条（允许缺失的角色除外）或多条时，拒绝本次同步，本机数据不变。
4. IPQC 数据库、日志、响应和浏览器里不出现 data-hub 访问令牌明文、刷新令牌明文、SMB 密码和 Excel 原始字节。
5. 看板口径与 [26-11-09 IPQC智能质量工作台](./26-11-09%20IPQC智能质量工作台.md) 一致。无台账仍显示「—」，不用 0 填充。

## 2. 范围

### 本期做什么

- 「数据与设置」增加「从共享盘同步」：选择本人的 `ready` 绑定、填写相对共享根的目录（可空），先核对文件，再确认写入本机。
- IPQC API 保存该用户的 data-hub **刷新令牌密文**（AES-256-GCM）。同步时换出访问令牌，用完即丢，不写入数据库。
- IPQC API 只代发 data-hub 已对 OAuth `mcp:read` 开放的只读请求，以及下面约定的表格读取。
- 按第 4 节把表格快照映射为现有 `IpqcDb` 里来自源表的那些数组，返回给浏览器。浏览器确认后写入现有 localStorage。
- 同步前仍可用现有「导出 JSON」。

### 明确不做什么

- 不改 data-hub 的登录页、OAuth 范围、SMB 凭据接口、管理接口和共享盘写操作。
- 不在 IPQC 引入 SMB 客户端，不让浏览器直连共享路径或 data-hub。
- 不把台账行写入 PostgreSQL，不做多人同时编辑，不做增量水位。
- 不覆盖培训资料、培训记录、考核、技能矩阵（`trn` / `exam` / `skill`）。这些表本期没有对应源文件。
- 不在 IPQC 里维护共享盘绑定、测试连接或保存 SMB 密码。
- 不改各车间 KPI 计算公式，不改 `.github/`。

### 外部前提（不在本仓库实现）

data-hub 与 IPQC 的 REST 前缀都是 `/api`，没有 `v1`。代读使用 `GET /api/shares`、`GET /api/search/files` 和下面的表格接口。

data-hub 现行规格规定：`xls` / `xlsx` 只能看元数据，OAuth 令牌也不能取预览字节。因此 **IPQC 不能用现有** `GET /api/shares/{id}/content` **读出台账**。

本期开工前，data-hub 须另有规格并交付：

| 方法 | 路径 | 成功时的 `data` |
|---|---|---|
| `GET` | `/api/shares/{id}/workbook?path=` | `{ path, modifiedAt, sheets: [{ name, rows }] }` |

约定：

- `rows` 为字符串二维表，公式格用缓存显示值；读不出缓存时该格为空字符串，并在该工作表上带 `formulaWithoutCache: true`。
- 只接受扩展名 `xls`、`xlsx`。不返回原始字节、Base64 或文件流。
- OAuth `mcp:read` 可以调用。仍禁止凭据、打开共享、删除共享、ERP 与管理接口。
- 文件缺失为 404。类型不对为 400，`msg` 为 `bad_request`，`message` 说明不是表格。
- 超过 data-hub 自己的大小或行数上限时 400，`message` 说明超限，不截断后假装完整。

该接口未部署时，IPQC 同步直接失败，提示「data-hub 尚未提供表格读取」。不得改走二进制拼装。

## 3. 目标行为

| 场景 | 现在 | 改后 |
|---|---|---|
| 打开数据与设置 | 种子或本机编辑；来源表是静态说明 | 同样保留导出、导入、恢复种子。另有从共享盘同步 |
| 没有 `ready` 绑定 | 无 | 按钮可点，请求后提示去 data-hub 绑定共享盘。本机数据不变 |
| 目录下每个必选角色恰好一个文件 | 无 | 展示将写入的条数，确认后覆盖第 4 节列出的表 |
| 必选角色缺失或重名 | 无 | 列出角色和候选路径，不写入 |
| 注塑毛边没有首件源表 | 合格率为「—」 | 仍然允许同步；该责任区首件保持空，合格率仍为「—」 |
| 用户取消确认 | 无 | 本机数据不变 |
| 上次同步后的单元格修改 | 留在本机 | 再次确认同步后，被覆盖的表以共享盘为准。`trn` / `exam` / `skill` 保留 |
| 刷新令牌失效或授权被解除 | 无 | 同步失败，提示重新登录。本机数据不变。密文删除 |
| data-hub 表格接口不存在或返回超限 | 无 | 同步失败，本机数据不变 |

## 5. 交互、会话与接口

- 页面仍是 `/data`。同步控件放在「数据与设置」卡片内，与导出、导入、恢复种子并列。
- 不新增 SMB 表单。绑定列表只显示 data-hub 返回的绑定 id、显示名和状态；非 `ready` 的绑定不可选，并显示 data-hub 原有状态文案。
- 目录为相对路径，空字符串表示该绑定的根。拒绝 `..`、盘符和 UNC。
- 先请求核对结果。核对成功只展示各角色路径、修改时间和将写入的条数，不改 localStorage。用户确认后再把快照写入本机。
- IPQC 会话仍是现有 HttpOnly Cookie。data-hub 访问令牌只放在当次同步的内存里。
- 刷新令牌只在服务端以密文存放，跟本地用户 id 一对一。退出 IPQC 时删除该密文。日志不写令牌、授权码、表格单元格和路径中的凭据。
- 缺少 `DATA_HUB_TOKEN_KEY`（32 字节密钥的 Base64）时 API 拒绝启动。不使用默认密钥。

接口前缀 `/api`。Controller 只返回业务体。

| 方法 | 路径 | 成功时的 `data` |
|---|---|---|
| `GET` | `/api/ledger-sync/shares` | `{ list, total, page, pageSize }`。列表项为 `{ id, name, status }`，仅当前用户在 data-hub 的绑定 |
| `POST` | `/api/ledger-sync/preview` | `{ files, counts }`。`files` 为角色、路径、`modifiedAt`；`counts` 为即将覆盖的各表条数。不返回整表 |
| `POST` | `/api/ledger-sync` | `{ counts, snapshot }`。`snapshot` 为通过 `isIpqcDb` 的对象，其中未覆盖的三张表为空数组，由浏览器与确认前的本机库合并 |

两个 `POST` 的请求体都是 `{ shareId, rootPath }`。`shareId` 必须是 UUID。未登录 401。`shareId` 不属于该 data-hub 用户、或绑定不是 `ready` 时 404，`message` 为「找不到可用的共享盘」。核对失败 400，`message` 列出原因。data-hub 令牌失效 401，`message` 为「data-hub 授权已失效，请重新登录」。

`page` 从 1，`pageSize` 默认 10、最大 100。绑定一般很少，仍按该形状返回。

## 6. 验收

1. 未登录不能调用上述三个接口。
2. 已登录且 data-hub 无 `ready` 绑定时，页面提示去 data-hub 绑定，本机台账条数不变。
3. 必选文件齐全且无重名时，核对接口不改本机；确认后首件、终检、投诉、点检、绩效与共享盘一致，培训三张表仍是确认前的内容。
4. 抽走一本必选终检台账后再同步，请求失败，本机仍是上一次确认后的数据。
5. 没有毛边首件文件时可以同步，毛边首件合格率仍为「—」。
6. 同一角色两条路径时失败，响应里能看到两条路径。
7. 列名不符或 data-hub 返回超限时失败，本机不变。
8. 数据库里刷新令牌字段不是明文；接口响应、浏览器存储和日志中没有访问令牌、刷新令牌明文和 SMB 密码。
9. 退出后密文已删除，再次同步会要求重新登录 data-hub。
10. data-hub 未提供 `GET /api/shares/{id}/workbook` 时，同步失败且提示尚未提供表格读取，IPQC 进程不访问 445 端口。
