本文件取代 11 月 19 日规格里的三件事：空目录表示整盘同步、按搜索和路径优先级挑选文件、核对结果只返回命中角色。文件名角色、列映射、令牌与安全仍以那份规格为准。扩展名规则、可选角色和预览响应以本文件为准。

## 1. 目标

用户在「数据与设置」页面选择一个或多个共享盘文件夹，也可以选择单个文件。选择文件夹时，系统递归包含该文件夹下的文件；用户可以展开目录，取消某个文件或整个子目录。系统只对最终选择范围做解析，并在同步前展示每个文件的处理结果。

本期解析 `.xls`、`.xlsx`、`.csv`，扩展名忽略大小写。文件夹内的其他文件不会被解析，但必须在核对结果中显示为「不支持」并说明原因。Excel/CSV 文件如果无法识别为任何 IPQC 台账角色，也必须显示为「未识别」，不能静默忽略。

同步仍先核对。核对不修改服务器台账。存在阻止项时不能进入写入。没有阻止项之后如何写入、是否覆盖、培训表是否改动，见 [26-11-21 服务器台账与定时同步](./26-11-21%20服务器台账与定时同步.md)。

可选缺失只有注塑毛边首件。注塑毛边终检与其他必需角色一样，缺失时阻止确认。

## 2. 范围与非目标

### 2.1 本期范围

- 共享盘目录树同时展示目录和文件。选择器只使用目录接口返回的路径。
- 勾选文件夹后，该文件夹下每个文件都进入核对结果。
- 支持取消单个文件，或取消整个子目录。
- 预览结果返回选中范围内每一个文件的处理状态。
- 后端按最终文件集合做角色匹配、表格读取和台账映射，不再按路径打分取舍。
- data-hub 的统一 workbook 接口扩展 CSV，返回 `sheets/rows` 结构。
- 保留 data-hub OAuth 授权和只读预览。台账写入、JSON 导入导出和种子数据不在本文件范围。
- 落地时同步修改 `docs/项目-业务约定.md` 里的共享盘同步请求和响应。

### 2.2 非目标

- 不让浏览器直接访问 SMB 或读取原始文件流。
- 不在 IPQC 保存 SMB 用户名、密码或访问令牌明文。
- 不改变本文件已经规定的文件名角色和扩展名规则。字段最终存哪、定时同步和多人共用服务器台账，见服务器台账规格。
- 不把不支持格式转换成可解析格式。
- 不让用户手填路径。

## 3. 现状问题

当前页面使用多选目录，接口提交 `rootPaths`。空选择表示整盘同步。服务端通过全盘搜索和路径优先级自动挑选文件：同一角色有多条命中时，可能静默留下分数较高的一条。页面无法表达「取消某个文件」，也无法看见目录里被忽略的文件。

现有 `/shares/:shareId/entries` 已返回 `file` 和 `directory`，但 IPQC 服务端只把目录返回给页面。

## 4. 采用方案：提交选中目录、单文件和排除路径

前端提交 `selectedEntries` 与 `excludedPaths`。服务端递归展开选中目录，合并单独勾选的文件，再减去排除路径，然后做角色匹配和解析。

同一路径只保留一条。路径比较忽略大小写，分隔符统一为 `/`。单独勾选的文件优先于排除路径：它即使落在被排除的目录下，仍然参与解析。

`excludedPaths` 可以是文件或目录。目录表示排除该目录下的全部后代，但挡不住单独勾选的文件。落在任何选中范围之外的排除路径直接忽略。

预览与正式同步使用同一套展开、排除和匹配逻辑。

## 5. 页面设计

### 5.1 三步流程

1. 选择已授权且状态为 `ready` 的共享盘。
2. 打开文件选择器，勾选目录或文件，并维护排除项。
3. 查看核对结果。没有阻止项时才能进入写入。写入目标见服务器台账规格。

没有选中任何目录或文件时，「核对文件」按钮禁用。空选择不再表示整盘同步。

### 5.2 文件选择器

文件选择器使用懒加载目录树。节点只来自目录接口：

- `directory`：可展开、可勾选；
- `file`：显示文件名和扩展名，可勾选。

勾选目录表示递归包含其下全部文件。取消其中一部分文件后，目录显示半选。取消子目录时，把该子目录路径放入排除集合。某个已勾选目录下的文件全部被排除、且其中没有单独勾选的文件时，该目录回到未选。

多个选中目录重叠时，文件去重。

选择器底部显示：已选目录数量、已选单文件数量、已排除文件数量、待核对提示。

### 5.3 核对结果

核对结果按文件展示，而不是只展示成功匹配的角色。文件按路径升序排列。

| 筛选 | 包含的状态 |
|---|---|
| 全部文件 | 候选集合中的每个文件，含已排除 |
| 可解析 | `parsed` |
| 未解析 | `unrecognized`、`unsupported` |
| 存在问题 | `duplicate`、`invalid` |

必需角色缺失显示在列表上方，不占文件行。未识别和不支持的文件出现在「未解析」中，确认区同时能看到它们。

每行显示：文件名、相对共享盘根的路径、扩展名、处理状态、原因、识别角色、修改时间。修改时间只在 workbook 读取成功时带回；没有则显示「—」。

页面顶部使用 `summary`，例如「选中 42 个文件，已解析 16 个，未解析 26 个」。这里的选中数含已排除文件。

### 5.4 处理状态

| 状态 | 说明 | 是否阻止确认 |
|---|---|---|
| `parsed` | 类型支持、角色识别且解析成功 | 否 |
| `unrecognized` | xls / xlsx / csv，但文件名未对应台账角色 | 否 |
| `unsupported` | 其他扩展名，或 data-hub 还不能读取 CSV | 否 |
| `excluded` | 用户主动取消 | 否 |
| `duplicate` | 同一角色有两个及以上文件 | 是 |
| `invalid` | 文件不存在、损坏、超限、列缺失，或印刷履历使用了 CSV | 是 |

同一角色的每个重复文件都标为 `duplicate`，并在问题里列出全部路径。不再按「2026 年」「AI 文件夹」等路径打分留下其中一条。

必需角色缺失同样阻止确认，并列出缺失角色。只有注塑毛边首件可以缺失。

## 6. API 与领域模型

### 6.1 目录接口

保留：

```text
GET /api/ledger-sync/shares/:shareId/entries?path=
```

返回目录和文件两类节点：

```ts
{
  list: Array<{
    name: string
    path: string
    kind: 'directory' | 'file'
  }>
}
```

页面不得只过滤目录。这个接口不返回修改时间。

### 6.2 预览与同步请求

新的请求体：

```ts
{
  shareId: string
  selectedEntries: Array<{
    path: string
    kind: 'directory' | 'file'
  }>
  excludedPaths: string[]
}
```

选择器只提交目录接口返回的路径，用户不能手填。正常点选不会出现「路径非法」。

服务端仍校验请求体：拒绝 `..`、盘符和 UNC。这类请求返回 400，`message` 说明路径无效。页面不为这条错误单独做提示。目录路径允许空字符串，表示共享盘根；文件路径不允许为空。

`selectedEntries` 为空时返回 400。请求里同时出现 `selectedEntries` 和旧的 `rootPath` / `rootPaths` 时返回 400。

兼容期内，只带 `rootPath` / `rootPaths` 的旧请求仍走原来的全盘搜索和路径优先级。新页面不再发送这两个字段。兼容逻辑在后续版本移除。

同步请求在上述字段之外，带上一次预览里每个文件的路径和修改时间：

```ts
{
  previewFiles: Array<{
    path: string
    modifiedAt?: string
  }>
}
```

### 6.3 预览响应

文件已经展开时，预览返回 200。阻止确认的问题放在 `issues` 里，不把整份文件清单放到失败信封的 `data: null` 中。

```ts
{
  files: Array<{
    path: string
    name: string
    extension: string
    role?: string
    label?: string
    modifiedAt?: string
    status: 'parsed' | 'unrecognized' | 'unsupported' | 'excluded' | 'duplicate' | 'invalid'
    reason?: string
  }>
  counts?: Record<string, number>
  summary: {
    total: number
    parsed: number
    unparsed: number
    unsupported: number
    excluded: number
    problem: number
  }
  issues: Array<{
    type: 'missing_role' | 'duplicate' | 'invalid' | 'column_mismatch' | 'read_failed'
    message: string
    role?: string
    paths?: string[]
  }>
}
```

`summary.total` 含已排除文件。`unparsed` 等于未识别加不支持。`problem` 等于 `duplicate` 与 `invalid` 的文件数，加上 `missing_role` 的条数。

`counts` 只表示各表即将写入的条数，与 11 月 19 日规格里的含义相同。存在阻止项时不返回 `counts`。预览不返回 `snapshot`。

正式同步成功时返回 `counts`、`snapshot`、检查得分，以及与预览相同的 `files`。

### 6.4 服务端解析流程

1. 校验共享盘属于当前 data-hub 用户且状态为 `ready`。
2. 校验并规范化路径。展开时只使用目录接口返回的子项，不跟随快捷方式；已访问过的路径跳过。
3. 任一子目录列出失败时，本次预览或同步直接失败，不返回部分文件清单。`message` 写明失败路径。
4. 递归读取选中目录，合并单独勾选的文件，形成候选集合。排除路径从候选集合中划出，被划出的文件仍进入结果，状态为 `excluded`。
5. 候选集合为空时仍返回 200。`issues` 列出缺失的必需角色，并说明所选范围没有文件。
6. 只对实际解析集合中的 `.xls`、`.xlsx`、`.csv` 调用 workbook。判断扩展名时忽略大小写。其他扩展名记为 `unsupported`。
7. 按第 7 节的文件名规则匹配 `LedgerRole`。未匹配的记为 `unrecognized`。
8. 同一角色有两个及以上文件时，这些文件全部记为 `duplicate`。
9. 角色重复、必需角色缺失、列映射失败和 workbook 读取失败写入 `issues`，并阻止确认。
10. 预览不写服务器台账。
11. 立即同步再次执行同一套展开和解析。请求若带 `previewFiles`，实际解析集合出现新增、缺失，或同一路径的 `modifiedAt` 变化时，拒绝写入，`message` 为「共享盘文件已变化，请重新核对」。没有 `modifiedAt` 的文件只比较路径是否还在。写入结果不再返回给浏览器覆盖本地的快照，响应见服务器台账规格。旧的 `POST /api/ledger-sync` 返回 410。

文件类型集中登记：

```ts
const SUPPORTED_FILE_TYPES = ['xls', 'xlsx', 'csv'] as const
```

解析器接收统一的 workbook 结构。除第 7 节写明的印刷履历外，角色映射不单独处理 CSV。

## 7. 角色、扩展名与 CSV

角色和列名沿用 11 月 19 日规格，不新增 CSV 专用角色。原来写死 `.xls` / `.xlsx` 的文件名，同时接受 `.csv`。比较忽略大小写。

印刷品质履历例外。该角色要读「首件」和「终检」两张工作表。CSV 只有一张表，因此印刷履历仍只接受 xls/xlsx。同名 CSV 的状态为 `invalid`，原因写明该角色需要两张工作表。

其余角色读取第一张表。CSV workbook 固定返回这一张表：

```json
{
  "path": "2026/注塑首巡检.csv",
  "modifiedAt": "2026-11-20T10:00:00Z",
  "sheets": [
    {
      "name": "csv",
      "rows": [
        ["日期", "料号", "问题"],
        ["2026-11-20", "A001", "尺寸异常"]
      ]
    }
  ]
}
```

IPQC 不读取 CSV 原始字节。编码、分隔符和行列转换由 data-hub 完成。

data-hub 还不能读取 CSV 时，这些 CSV 的状态为 `unsupported`，原因是「data-hub 尚未提供 CSV 读取」。它们不算作已满足的角色。必需角色因此缺失时，按缺失阻止确认。没有任何必需角色依赖这些 CSV 时，允许继续，并在「未解析」中可见。

## 8. 错误与数据安全

| 情况 | 结果 |
|---|---|
| 未登录，或 data-hub 授权失效 | 401。授权失效时提示重新授权，并清理服务端刷新令牌密文 |
| 共享盘不属于当前用户，或状态不是 `ready` | 404，提示去 data-hub 完成绑定 |
| 请求体带 `..`、盘符、UNC，选择为空，或新旧字段混用 | 400 |
| 子目录列出失败 | 400，不返回部分清单 |
| 文件已展开，但有重复、无效、缺必需角色或列不匹配 | 预览 200，`issues` 阻止确认。直接调用同步时 400 |
| 核对之后文件有增删或修改时间变化 | 同步 400，提示重新核对 |
| 所选范围没有文件 | 预览 200，列出缺失的必需角色 |

不支持和不识别本身不阻止确认。文件在点选之后被删除，状态为 `invalid`，原因是「文件不存在」，这不属于路径非法。

任何失败都不改变服务器台账。响应和日志中不保存 OAuth 令牌、SMB 密码或原始文件字节。

## 10. 验收条件

1. 勾选文件夹后，目录下所有文件都出现在核对结果中，包括不支持和未识别的文件。
2. 取消一个文件后，该文件状态为「已排除」，不参与角色匹配和写入。取消子目录后，其下文件同样排除；单独勾选的文件仍然参与解析。
3. 文件夹内的 PDF、Word、图片等文件显示为「不支持」，并说明扩展名。`.XLS` 这类大小写不同的扩展名按表格处理。
4. `.xls`、`.xlsx`、`.csv` 无法对应角色时显示为「未识别」，不静默消失。
5. 同一角色存在多个文件时，全部路径都可见，并阻止确认。目录里同时有 2024 与 2026 两本同角色台账时，也不自动留下 2026 那本。
6. 必需角色缺失时阻止确认。注塑毛边首件缺失时允许继续。注塑毛边终检缺失时阻止确认。
7. 单表角色的 CSV 按 workbook 的第一张表参与解析。印刷履历 CSV 显示为无效并阻止确认。data-hub 不能读 CSV 时，相关文件显示「尚未提供 CSV 读取」；因此缺必需角色时不能确认。
8. 有阻止项时，预览仍返回文件清单，确认按钮不可用；直接提交同步会被拒绝。
9. 核对阶段不改变服务器台账。核对后文件发生变化时，本次不写入。确认之后的合并、保留和定时更新见服务器台账规格。
10. data-hub 授权失效、目录列出失败或列映射失败时，服务器台账保持上一次成功同步的结果。
11. data-hub 授权流程继续可用。JSON 导入、恢复种子不再作为本文件的验收项。

## 11. 已定边界

- CSV 沿用现有角色和列名，扩展名按第 7 节放宽；印刷履历不接受 CSV。
- 「未识别」和「不支持」允许继续同步，且必须出现在「未解析」和确认区。
- data-hub 的 CSV workbook 是外部前提，需要与 data-hub 规格一起交付。未交付时按第 7 节显式失败，不能当成同步成功。
