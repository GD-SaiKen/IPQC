# 后端规范（语言无关）

与前端共同的 URL、动词、响应信封、分页与写操作 `data` 见 [SKILL.md](SKILL.md)「前后端统一约定」。  
本节只规定**服务端怎么分层、模块边界、业务代码返回什么**。Nest 的目录、装饰器、Prisma 见 [nest.md](nest.md)。

领域表、路由前缀、错误文案以仓库 `docs/项目-业务约定.md` 与 `docs/SDD/` 为准。

## 1. 三层

```text
HTTP → 接入层 → 领域层 → 数据访问层
```

| 层 | 职责 | 不负责 |
|----|------|--------|
| **接入层** | 路由、解析参数、鉴权标记、读写 Cookie/Header、把领域结果原样返回 | 业务规则、拼 SQL、哈希密码、手写响应信封 |
| **领域层** | 校验与编排、事务、软删、唯一冲突转成可读错误、决定返回哪份字段 | HTTP 状态码表、Swagger、框架响应包装 |
| **数据访问层** | 按条件读写存储、限定查询字段 | 对外 HTTP、跨模块编排 |

- 常规增删改查：领域层直接使用本模块的数据访问入口即可，不必为每个模块再包一层仓储。
- **需要替换实现，或要实现共享库里的接口**时，再单独做仓储（例如按登录名取用户、登录成功回写 IP）。
- 模块之间只调用对方的**领域层**（或共享库已导出的服务）。禁止注入对方的仓储，禁止在本模块里直接改对方的表。

接入层返回的是 [SKILL.md](SKILL.md) 里的 **`data`**。信封由应用入口统一包装：`message` 为中文提示，`msg` 为英文标识。业务代码不组装这两个字段；抛异常时的文案用中文，由过滤器写入 `message`。

失败用框架的异常（参数错误、未找到、无权限等），由统一异常处理写成失败信封。日志可记请求与错误，密码、令牌、Cookie 必须脱敏。

## 2. 目录与测试

本节目录适用于 **TypeScript** 应用。Go 的包布局与 `*_test.go` 见 [go.md](go.md)，不要把 Go 测试放进 `__test__/`。

应用根目录（单应用即包根，monorepo 即 `apps/<app>/`）**不**再套一层 `src`。

```text
apps/<app>/
├── main.ts
├── app.module.ts          # 名称随应用
├── common/                # 分页、信封、操作结果等，跨模块复用
├── modules/<domain>/      # 业务模块，一领域一目录
└── __test__/              # 测试；子路径与被测文件一一对应
```

被测文件与测试文件只差 `__test__/` 前缀和 `.test.ts` 后缀：

| 被测 | 测试 |
|------|------|
| `modules/user/user.service.ts` | `__test__/modules/user/user.service.test.ts` |
| `modules/user/dto/create-user.dto.ts` | `__test__/modules/user/dto/create-user.dto.test.ts` |
| `common/utils/pagination.ts` | `__test__/common/utils/pagination.test.ts` |

新建测试只放 `__test__/`。不要在 `modules/` 或 `common/` 旁边新建 `*.test.ts`，也不要再使用 `test/` 目录做单元测试。

## 3. 一个业务模块里有什么

一领域一模块，目录为 `modules/<domain>/`。标准资源至少包含：

| 概念 | 内容 |
|------|------|
| 模块装配 | 注册接入层与领域层；需要被别的模块调用时导出领域层 |
| 接入 | 本资源的路由与入参 |
| 领域 | 创建、列表、详情、更新、删除 |
| 入参模型 | 创建、部分更新、列表筛选（含分页） |
| 出参模型 | 列表项、列表（含 total/page/pageSize）、详情；只描述返回字段 |

筛选入参继承公共分页（`page`、`pageSize`）。部分更新是创建入参的可选子集，不复制一整份字段定义。

鉴权、上传、跨模块编排可以在同一模块里增加常量、守卫、装饰器，不必套进 CRUD 清单。

## 4. 领域层返回的业务载荷

与 [SKILL.md](SKILL.md) 的 `data` 形状一致，此处是领域层的返回值，尚未包信封：

| 操作 | 返回 |
|------|------|
| 列表 | `{ list, total, page, pageSize }`，默认按主键倒序 |
| 详情 | 单条；不存在则按「未找到」失败 |
| 创建 | 新建资源（至少含标识；密码等敏感字段不出现） |
| 更新 | `{ id, updated: true }`；没有任何可写字段则失败；目标不存在则失败 |
| 删除 | `{ id, deleted: true }` |
| 无业务体 | `{ ok: true }` |

列表与详情使用明确的字段集合，不 `select *` 把密码带出去。部分更新只提交调用方真正传入的字段。

分页在运行时再限制：`page >= 1`，`pageSize` 有上限，过深的 offset 直接拒绝。

## 5. 数据与安全（与 ORM 品牌无关）

- 库列 **snake_case**，接口与模型属性 **camelCase**。
- 删除默认**软删**（删除标记），列表与详情不包含已删行。
- 写操作记录操作人（创建人、更新人）；详情需要展示名时在领域层组装，不把关联对象原样甩给接口。
- 密码只存哈希；配置项（盐轮数、连接串、密钥）来自环境变量，示例文件不含真值。
- 生产结构变更走迁移，不用启动时自动改表。
- 对外时间格式以本期 SDD 为准；转换放在领域层边界，不要在接入层临时改。

## 6. 定时与批量导入

- 依赖外部文件或接口时，读取失败则本轮不基于新数据执行，保留当前生效数据。
- 导入：表头或格式错误则整批失败；成功则同一事务写入批次与明细，再切换「当前生效」。
- 通知类任务要有去重键。重试次数与字段映射写在规格里，不写死在规范中。
